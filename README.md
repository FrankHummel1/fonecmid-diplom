# Управление IT-фирмой: доработка для «Ваш компьютерный мастер»

Дипломный проект профессии «1С-программист: с нуля до middle» (Нетология).
Текст задания перенесён в [TASK.md](TASK.md), подробные требования лежат в папке [tasks](tasks).

Конфигурация «Управление IT-фирмой» (БСП 3.1.9, платформа 8.3.27) доработана в 1C:EDT.
Все добавленные объекты имеют префикс `ВКМ_` и входят в служебную подсистему `ВКМ_ДобавленныеОбъекты`.
Изменения в коде поставщика выделены комментариями `//+Симиненко ДД.ММ` (добавлено)
и `//-Симиненко ДД.ММ` (старый код закомментирован).

## Состав доработки

**Подсистема «Обслуживание клиентов»**

| Объект | Назначение |
|---|---|
| Перечисление `ВидыДоговоровКонтрагентов.ВКМ_АбонентскоеОбслуживание` | новый вид договора |
| Справочник `ДоговорыКонтрагентов` | реквизиты абонентского договора, форма `ВКМ_ФормаЭлемента` с программным выводом полей |
| Справочник `ВКМ_Сотрудники` | специалисты и административный персонал |
| Документ `ВКМ_ОбслуживаниеКлиента` | заявка клиента: планирование, выполненные работы, присоединённые файлы (лист учёта) |
| Регистр накопления `ВКМ_ВыполненныеКлиентуРаботы` | часы и суммы к оплате клиентом |
| Регистр накопления `ВКМ_ВыставленныеАкты` | услуги, выставленные актами (документ `РеализацияТоваровУслуг`) |
| Константы `ВКМ_ТокенТелеграмБота`, `ВКМ_ИдентификаторГруппыТелеграм` | интеграция с Телеграм |
| Справочник `ВКМ_УведомленияТелеграмБоту`, общий модуль `ВКМ_Телеграм`, регламентное задание `ВКМ_ОтправкаУведомленийТелеграм` | очередь и отправка уведомлений о заявках |
| Константы `ВКМ_НоменклатураАбонентскаяПлата`, `ВКМ_НоменклатураРаботыСпециалиста` | услуги для автозаполнения актов |
| Документ `РеализацияТоваровУслуг` (доработан) | команда «Заполнить», метод `ВКМ_ВыполнитьАвтозаполнение`, печатная форма «Акт об оказанных услугах» (макет `ВКМ_ПФ_MXL_АктОбОказанныхУслугах`) |
| Обработка `ВКМ_МассовоеСозданиеАктов` | массовое создание актов на длительных операциях БСП |
| Общая форма `ВКМ_НастройкиОбслуживанияКлиентов` | заполнение констант подсистемы |

**Подсистема «Расчёт управленческой зарплаты»**

| Объект | Назначение |
|---|---|
| Планы видов расчёта `ВКМ_ОсновныеНачисления` (Оклад, ПроцентОтРабот, Отпуск), `ВКМ_ДополнительныеНачисления` (Премия), `ВКМ_Удержания` (НДФЛ) | отпуск вытесняет оклад; база отпуска — все начисления |
| Регистры расчёта `ВКМ_ОсновныеНачисления`, `ВКМ_ДополнительныеНачисления`, `ВКМ_Удержания` | период действия, базовый период, график `ВКМ_ГрафикРаботы` |
| Регистр сведений `ВКМ_УсловияОплатыСотрудников` | оклад и процент от работ (периодичность — месяц) |
| Регистр сведений `ВКМ_ГрафикРаботы` | рабочие дни (заполняется пятидневкой автоматически) |
| Регистры накопления `ВКМ_ВыполненныеСотрудникомРаботы`, `ВКМ_ВзаиморасчетыССотрудниками`, `ВКМ_ЗапланированныеОтпуска` | выработка, взаиморасчёты, плановые отпуска |
| Документы `ВКМ_НачислениеЗарплаты`, `ВКМ_НачислениеФиксированнойПремии`, `ВКМ_ВыплатаЗарплаты`, `ВКМ_ГрафикОтпусков` | расчёт, премии, выплата, график отпусков с диаграммой Ганта |

**Отчёты** (СКД, только по регистрам): `ВКМ_ВыработкаСпециалистов`, `ВКМ_АнализВыставленныхАктов`,
`ВКМ_РасчетыССотрудниками`, `ВКМ_РасходЗапланированныхОтпусков`.

**Права**: роли `ВКМ_*`, поставляемые профили групп доступа «Специалист», «Менеджер», «Бухгалтер IT-фирмы», «Кадровик-расчетчик».

## Инструкция по начальной настройке

Действия выполняются в рабочей базе, где уже ведётся учёт в исходной конфигурации.

### 1. Обновление конфигурации

1. Сделайте резервную копию базы (Конфигуратор → Администрирование → Выгрузить информационную базу).
2. Загрузите доработанную конфигурацию из репозитория (EDT: обновить конфигурацию базы, или загрузите cf-файл в конфигураторе)
   и обновите конфигурацию базы данных.
3. Запустите базу под администратором. Версия конфигурации повышена до 1.0.2.1, поэтому БСП выполнит обновление
   информационной базы и создаст поставляемые профили групп доступа. Дождитесь окончания обновления.

### 2. Настройки обслуживания клиентов

Раздел **Обслуживание клиентов → Настройки обслуживания клиентов** (доступен администратору):

1. **Номенклатура абонентской платы** и **Номенклатура работ специалиста**: выберите (или предварительно создайте в
   справочнике «Номенклатура») две услуги, например «Абонентское обслуживание» и «Работы специалиста».
   Без них команда «Заполнить» в реализации и массовое создание актов выдадут ошибку.
2. **Токен телеграм-бота** и **Идентификатор группы**:
   - напишите [@BotFather](https://t.me/BotFather) команды `/start` и `/newbot`, задайте имя бота, скопируйте токен;
   - создайте группу в Телеграм, добавьте в неё бота и сделайте его администратором;
   - напишите в группу любое сообщение и откройте в браузере `https://api.telegram.org/bot<токен>/getUpdates`;
     значение `chat.id` (отрицательное число) — идентификатор группы.
3. Регламентное задание **«Отправка уведомлений в Телеграм (ВКМ)»** включено по умолчанию и запускается раз в минуту.
   Проверьте, что регламентные задания разрешены: Администрирование → Обслуживание → Регламентные и фоновые задания.
   В файловой базе задания выполняются, пока открыт хотя бы один сеанс.

### 3. Справочники и договоры

1. Заполните справочник **Сотрудники** (раздел «Расчёт управленческой зарплаты»). Для специалистов укажите
   пользователя программы.
2. Для клиентов на абонентском обслуживании создайте договоры с видом **«Абонентское обслуживание»**: укажите
   период действия, сумму ежемесячной абонентской платы и стоимость часа работы специалиста.

### 4. Условия оплаты сотрудников

В регистре **Условия оплаты сотрудников** введите для каждого сотрудника с месяца начала расчёта:
оклад и процент от работ. Для административного персонала процент — 0.
Документ «Обслуживание клиента» не проводится, если для специалиста на дату документа нет записи условий оплаты
(нулевой процент допустим).

### 5. График работы

Норма рабочих дней берётся из регистра **График работы**. При проведении начисления зарплаты он автоматически
дополняется пятидневной неделей за расчётный месяц и 12 предыдущих месяцев. Праздничные дни можно отметить
вручную (значение 0) в списке регистра — введённые вручную дни не перезаписываются.

### 6. Пользователи и права

Администрирование → Настройки пользователей и прав → Группы доступа: создайте группы доступа на основе
поставляемых профилей и включите в них пользователей:

| Профиль | Кому назначается | Что доступно |
|---|---|---|
| Специалист | специалисты | документы «Обслуживание клиента», присоединённые файлы, отчёт «Выработка специалистов» |
| Менеджер | менеджеры | документы «Обслуживание клиента», контрагенты и договоры |
| Бухгалтер IT-фирмы | бухгалтеры | реализации и акты, «Массовое создание актов», отчёт «Анализ выставленных актов», редактирование макета акта |
| Кадровик-расчетчик | кадровики | сотрудники, условия оплаты, документы зарплаты и отпусков, отчёты «Выработка специалистов», «Расчёты с сотрудниками», «Расход запланированных отпусков» |

### 7. Ежемесячная работа

1. Менеджер регистрирует заявки документом «Обслуживание клиента», специалист вносит выполненные работы и
   прикладывает скан листа учёта (команда «Присоединённые файлы»).
2. В начале месяца бухгалтер открывает **Массовое создание актов**, выбирает месяц и нажимает «Создать акты».
   Повторно акт по договору за месяц не создаётся. Акт печатается из документа реализации: Печать → «Акт об оказанных услугах».
3. Кадровик планирует отпуска документом **График отпусков** (строки сотрудников с суммой отпусков больше 28 дней
   подсвечиваются, кнопка «Анализ графика» показывает диаграмму Ганта), затем ежемесячно:
   **Начисление зарплаты** (кнопка «Заполнить» подставит оклад, процент от работ и отпуска из графика) →
   **Начисление фиксированной премии** при необходимости → **Выплата зарплаты** (кнопка «Заполнить» по задолженности).

## Автоматизированное тестирование

Сценарий Vanessa Automation: [tests/features/ВКМ_РаботаСЗаявкамиКлиентов.feature](tests/features/ВКМ_РаботаСЗаявкамиКлиентов.feature).
Он проверяет: планирование обслуживаний менеджером, закрытие их специалистом, массовое создание актов бухгалтером
и сравнение отчёта «Анализ выставленных актов» с эталоном.

### Подготовка базы

1. Разверните демонстрационную базу из dt-файла в разделе Releases (или подготовьте базу вручную по шагам ниже).
2. В базе должны быть:
   - пользователи **Менеджер**, **Специалист**, **Бухгалтер** без пароля, с профилями «Менеджер», «Специалист»,
     «Бухгалтер IT-фирмы» соответственно, и администратор;
   - контрагент **«ВКМ Тест»** и договор **«Абонентский договор VA»** с видом «Абонентское обслуживание»,
     периодом действия, включающим текущую дату, абонентской платой **5 000** и стоимостью часа **2 000**;
   - сотрудник **«Тестов Тест»** (пользователь — Специалист) с условиями оплаты: процент от работ 25;
   - заполненные константы номенклатуры для актов.
3. За текущий месяц по договору «Абонентский договор VA» не должно быть обслуживаний и актов: сценарий проверяет
   суммы именно текущего месяца (2 + 3 часа × 2 000 = 10 000 по работам и 15 000 в акте вместе с абонентской платой).
   Перед повторным запуском восстановите базу из dt или пометьте на удаление созданные тестом документы.

### Настройка окружения и запуск

1. Скачайте Vanessa Automation (single-версия `vanessa-automation-single.epf`) из
   [официального репозитория](https://github.com/Pr-Mex/vanessa-automation/releases).
2. Разрешите базе работать как тестируемой: запуск тест-клиентов выполняется с ключом `/TESTCLIENT`,
   VA делает это сама. Для файловой базы ничего дополнительно настраивать не нужно.
3. Запустите базу под администратором в режиме **менеджера тестирования**: в окне запуска 1С выберите базу →
   «1С:Предприятие» → «Дополнительно» → «Запускать как менеджер тестирования» (или ключ `/TESTMANAGER`).
4. Откройте `vanessa-automation-single.epf` (Файл → Открыть).
5. На закладке **«Сервис» → «Клиенты тестирования»** добавьте три строки с именами **Менеджер**, **Специалист**,
   **Бухгалтер**: тип клиента «Тонкий», строка соединения — путь к этой же базе (`File="C:\Bases\Diplom";`),
   логин — одноимённый пользователь, пароль пустой. Для порта тест-клиента используйте разные значения (например 48051–48053).
6. На закладке «Запуск сценариев» укажите каталог `tests/features` репозитория, нажмите «Загрузить сценарии»,
   затем «Выполнить сценарии».
7. Все четыре сценария должны завершиться зелёным статусом. Если отличается заголовок окна или имя элемента
   (это зависит от версии платформы), используйте в VA режим записи действий, чтобы уточнить шаг.
